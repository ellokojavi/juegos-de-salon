## D-429 · A preview of each PR on GitHub Pages, and review rounds on it instead of a PR per round
**Date:** 2026-10-22 · **Status:** current · **Relation:** extends D-409 (changes go to Labs first) and D-216 (auto-merge: a PR in review rounds is not ready) · **Topics:** publishing, agents
**Context:** asked why releases are slow, the analysis of October 20–22 found features split into many PRs
because the owner could only see a change once it merged: "1 al día"'s score took 8 PRs (lab, v2,
hifi, polish, tweaks, speed, redesign, launch), La Copa's create screen 4 and the recap 4. Each PR pays
a fixed ~15–25 minutes (agents, changelog, the checks, publishing). The owner chose GitHub Pages over
Cloudflare for the previews, to keep a single platform, and asked that it need no upkeep.
**Decision:** `.github/workflows/preview.yml` publishes each same-repo PR, merged with `main`, at
`ellokojavi.github.io/juegos-de-salon-previews/<branch>/` on every push, and comments the link on the PR.
The previews repo is separate so a preview can never touch the real site; it holds one commit without
history, is pushed with a deploy key (`PREVIEWS_DEPLOY_KEY`, which never expires) and publishes itself
with a Pages workflow that `update.sh` writes. Closing a PR deletes its folder, and each push deletes
the folders of PRs no longer open. Previews carry `noindex` and no `CNAME`, and count as test traffic
(`envOf`, `entorno`: a `*.github.io` host under `/juegos-de-salon-previews/`), so they don't reach the
panel or the rankings. While the owner reviews a change round by round, the session keeps the PR open
without auto-merge, pushes each round to it and points to the preview; it turns auto-merge on when the
owner approves.
**Why:** a review round costs a push (incremental checks, D-392) instead of a PR, and what merges is
what the owner already saw working. The lab gate is unchanged: the preview asks for the lab key too.
**Consequences:** setup is once (docs/PREVIEWS.md: the repo, Pages from Actions, the deploy key); after
that nothing is maintained. Without the secret, or if Pages fails, the `Preview` check says so and the
PR is unaffected. Forks get no preview. Rooms opened in a preview are real Firebase rooms, as in the lab.
