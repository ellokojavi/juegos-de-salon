## D-440 · The processes round runs from a visible scheduled task, with a watchdog on GitHub
**Date:** 2026-10-24 · **Status:** amended by D-451 · **Relation:** amends D-276 (where the round's task lives) and D-360 (when the ideas agent is dispatched); extends D-365 (the jobs registry) · **Topics:** agents
**Context:** D-276 moved the round to a scheduled task inside the Claude desktop app on the Mac mini, and paused the cloud tasks on 2026-10-11. That task ran daily from the 12th to the 18th and then stopped; one manual round ran on the 21st and nothing after. Nothing said so: 91 merges went unreviewed for six days until the owner noticed the agents were gone. The task was invisible from the owner's phone, its prompt lived only in the app, and the two paused cloud tasks still named `procesos.md` and `documentacion.md`, renamed to English since. Meanwhile the ideas agent, dispatched weekly by the round, stopped too, and its ledger still showed as "proposed" two ideas the owner had answered No to on #556.
**Decision:** owner's request ("continually improve the application"), in four parts. (1) The round and the weekly report are claude.ai scheduled tasks that run on the Mac mini ("Require this computer"), so they and each run's result show on the owner's phone; their prompt is one line that says to read `tools/jobs/prompts/<id>.md` from origin/main and follow it, and that file starts by stopping if today's round (or this week's report) already ran, so a second copy of the task never opens a second PR. (2) `round-watch.yml` runs daily at 17:17 UTC on GitHub, away from the Mac: when a commit on `main` has gone more than 24 hours without the round looking at it (after `checkedUpTo`), it opens the "Processes round missed" issue, and it closes it when the round catches up. A day with no merges never raises it. (3) `jobs.test.mjs` fails if an `app` job has no prompt file in the repo or its prompt names a file that does not exist. (4) The ideas agent is not dispatched while its last issue still has questions the owner has not ticked (`ideasWaiting` in `processes.mjs`): the round would only learn that and open nothing.
**Why:** an always-on process that can stop silently is worse than none, because everyone assumes it ran. The watchdog checks the outcome (unreviewed commits), not the task, so it catches every cause: the Mac asleep, the app closed, a broken prompt. Keeping prompts in the repo puts them under the same review and tests as everything else. The ideas gate follows D-338: the owner's attention, not idea supply, is the limit.
**Consequences:** `tools/agents/round-watch.mjs` (`check | notify`) and its test; `tools/jobs/prompts/`; `jobs.json` lists `round-watch` and names the new tasks; `jobs.mjs status` shows the round's last recorded date; `MAC-MINI.md`, `tools/jobs/README.md`, `CLAUDE.md` and `processes.md` say where the tasks live. `processes.mjs` keeps the watchdog's issue out of the owner's backlog. The old task in the desktop app on the Mac mini is turned off by the owner, by hand; if it runs anyway, the new prompt's once-a-day check stops the duplicate.
