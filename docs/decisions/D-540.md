## D-540 · A red PR the owner asked for in a session is approved by that session
**Date:** 2026-11-07 · **Status:** current · **Relation:** amends D-519 (who ticks a 🔴 PR) · **Topics:** publishing, agents
**Context:** a 🔴 PR born from a conversation (the owner asked for the change in a session) still waited for the owner to find the PR and tick its box, though the owner had already said they wanted the work done (#1273). Sessions act on GitHub as the owner's account, so they can tick the box themselves.
**Decision:** when the owner asked for the work directly in a session's dialogue, that session ticks the owner-approval box in the PR's description itself (as the owner, once the PR's head is final), so `approve-pr` and `merge` run as if the owner had tapped Yes. A 🔴 PR that no owner request in a dialogue started (an agent's round, a job, a scheduled task, a session's own initiative) still waits for the owner's tick. If unsure, wait.
**Why:** in a conversation the owner wants the work done by default; the gate still protects what agents produce on their own.
**Consequences:** the gate itself (that exact commit, `tests` and `end-to-end` green before merge) is unchanged; a later push asks again and the session ticks again. The session says in the PR that it ticked on the owner's request in a session.
