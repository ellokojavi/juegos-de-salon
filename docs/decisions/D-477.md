## D-477 · 📣 Campaigns is the control center for everything temporary: splash, site features and skins
**Date:** 2026-10-27 · **Status:** current · **Relation:** extends D-454 and D-457 · **Topics:** panel, home
**Context:** The owner asked for 📣 Campaigns to tell apart three kinds of things the site turns on for a while: the splash windows (D-351, D-454), the fixed features of the site (☕ Buy me a coffee, D-448) and the "skins" (the seasonal templates, D-457, like today's Halloween), so all the temporary activity is controlled from one place. Until now only the splash had switches; the coffee had only its numbers there, and a skin could only be moved or stopped with a PR.
**Decision:** 📣 Campaigns has three tabs, each saying under its name what is on today: **📣 Splash** (as before), **🧩 Site features** (one card per feature with a switch per place it shows: for ☕ the home footer link and the end-of-game invitation; its numbers below) and **🎨 Skins** (one card per template: *Every year* by its own days, *These days* with a start and an end date, or *Off*). The new switches live in Firebase `controls/` (public read, owner write, shape checked by the rules): `controls/skins/<id> = { mode: 'yearly'|'dates'|'off', from?, until?, at }` and `controls/features/<id> = { <part>: bool, at }`. The site reads them through `public/assets/js/controls.js`: the home page fetches `controls.json` on each visit (1.5 s at most, else the device's last copy, else the code) before choosing the skin and drawing the footer link, and keeps the answer on the device; a game's ending reads only that copy, so it never adds a Firebase read to a game. With nothing saved, everything is as the code says; `?test` ignores them.
**Why:** One screen to know what the site shows players today and to change it from a phone without a PR, as the splash already did. Each kind keeps the controls that fit it: a splash is dated and ordered, a feature is switched per place, a skin is a yearly date that can be moved or skipped.
**Consequences:** A new feature is a row in `FUNCIONES` (`public/panel/panel.js`) and a `featureOn(...)` where the site shows it; a new skin needs nothing in the panel (it lists `TEMPLATES`). An end-of-game switch reaches a player from their next home page visit. `firebase/controls.test.mjs` checks the rules, `public/assets/js/controls.test.mjs` the reading and `public/panel/campaigns.test.mjs` the skins' days.
