## D-467 · Cache busting by content hash, not by release
**Date:** 2026-10-27 · **Status:** current · **Relation:** amends D-22 and D-205 · **Topics:** publishing
**Context:** `set-version.py` gave every module, stylesheet, classic script and card image the same `?v=X.Y.Z-<commit>`. With several merges a day, every returning player downloaded all ~200 modules again after each publish, even when one file changed (issue #847, audit #834).
**Decision:** On publish each file gets `?h=<first 8 hex of the sha256 of its bytes>`, in the import map and in the stylesheet, modulepreload, classic script and og:image URLs. Every module import is relative or an https URL, so it resolves to a URL the map covers and a module's own hash is enough for nested and dynamic imports. The release (`X.Y.Z-<commit>`) moves to `<meta name="release">`: `versionOf` (stats.js), the watchdog (vigia.js) and publish.yml's live check read it there; the footer version stays.
**Why:** a publish that changes one module invalidates only that module (and the pages' HTML); the stamp stays reproducible (same tree, same hashes).
**Consequences:** each page still lists every module (trimming the map per page was left out: optional, and it needs the import graph in Python). A tab left open across a deploy still asks GitHub Pages for files by path, which ignores the query, so mixed old and new code is still possible for its dynamic imports.
