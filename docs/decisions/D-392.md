## D-392 · A push to a PR tests only what changed since the PR last passed
**Date:** 2026-10-20 · **Status:** current · **Relation:** extends D-329 (the scope) and D-308 (the marks of what passed); amends D-391 (its proposed phases) · **Topics:** tests
**Context:** a PR is pushed several times, and each push ran the end-to-end scope of the whole PR: #572 ran
all 76 jobs three times for commits that touched no page (a test, the README seal, a changelog entry).
Asked whether to build D-391's proposed ledger and audit, the owner chose this instead.
**Decision:** each PR run that passes `end-to-end` leaves an artifact `e2e-head-<sha>` for the PR's head
commit. `tools/e2e/since-passed.mjs` finds the PR's last earlier commit with that mark and gives the
scope only the files changed since it (GitHub's compare, merges of `main` included). The whole PR is tested
on the first push, after a red run, after a force push, when the compare reaches GitHub's 300-file limit
or when asking fails. Of D-391's phases, the ledger with a daily audit and the module of declared facts
are dropped; the feedback left is a ⚠️ line in the run summary when a run goes over its level's budget,
and a line in the merged PR's comment when a script it skipped fails on `main` (to build).
**Why:** the push is what is new; what passed before still passes unless a changed file reaches it. A
daily audit would cost every day what the guards already catch in the PR.
**Consequences:** a fix pushed after a green run runs only its own scope (none for a doc or a test).
Changes on `main` the PR did not merge are not retested on the PR; `publish.yml` runs the whole suite
on what it publishes unless that tree passed (D-302, D-308), and an incremental run never leaves the
tree's mark, so after a PR whose last push was incremental, publishing runs the whole suite. The design is in
`docs/TEST-SCOPE.md`; `since-passed.test.mjs` tests the choice.
