## D-394 · One file per decision, and a generated index
**Date:** 2026-10-20 · **Status:** current · **Relation:** amends D-301 (the merge driver of DECISIONES.md goes; the reservation stays) and D-213 (the history lives in docs/decisions/); completes D-316 (the decisions' structure is English) · **Topics:** agents
**Context:** docs/DECISIONES.md had reached 389 decisions, 7,400 lines and about 700 KB (some 175k
tokens), growing by several a day. The owner asked whether it was a problem and what the right
long-term choice was, weighing efficiency, token cost, security, reliability and scalability.
Agents could not read it whole and searched inside it; every PR edited the same file, which needed
its own merge driver (D-301); a bad merge could damage hundreds of decisions at once; and the
amended-by links between decisions were checked only from one big text. Archiving the ones no
longer in force would have removed only 9 of 389.
**Decision:** each decision is its own file, `docs/decisions/D-<n>.md`: its heading, a meta line
(`**Date:** · **Status:** · **Relation:** · **Topics:**`, labels and Status values in English) and
its text. `docs/DECISIONS.md` is the index, generated by `node tools/agents/decision.mjs index` from
the files and `docs/decisions/topics.json` (the topic table, then the decisions in force and those no
longer in force, one row each), never edited by hand. `decision.mjs reserve` reserves the number as
before and writes the file's skeleton. The paths table of the old head is `docs/decisions/PATHS.md`.
The split moved the text word for word (only the relative links got `../`) and gave every title in
English; the 314 bodies still in Spanish are translated in phases by the processes round (D-354),
not in this change, so the move could be checked word for word.
**Why:** reading one decision costs a page instead of the whole history, and the index (about 12k
tokens) says which to open. Two PRs with new decisions touch different files, so the driver is no
longer needed; a mistake stays in one small file; and the checks now cover the files themselves.
**Consequences:** `document.mjs` and `document.test.mjs` check that each file is named after its
heading, uses the English labels and known topics, that Statuses and Relations agree, and that the
index is up to date. A branch from before this change that still has docs/DECISIONES.md runs
`node tools/agents/decision.mjs split`, which writes its new decisions as files and names the
older ones it changed, to be carried over by hand. If the index collides when bringing in main, it
is built again with `decision.mjs index`.
