## D-413 · The lab's fast lane: the session does a lab-only change itself, without agents
**Date:** 2026-10-21 · **Status:** amended by D-519 · **Relation:** corrects D-304 (what a lab-only PR runs before merging) · **Topics:** agents
**Context:** six cosmetic changes to one lab page (`/labs/daily-score/live/`) took about 40 minutes:
a build agent (~10 min), the usability and documentation agents (~2 min), then waiting for both,
for CI's end to end (~9 min) and for publishing. The agents found nothing to fix on that PR or on
the two before it. The owner asked to cut it substantially for this and other lab work.
**Decision:** a **lab-only PR** (`covers.mjs check` says 🧪: everything in `public/` is under
`public/labs/`) takes the fast lane:
- The session makes the change itself, with no build agent, unless the work is large (new screens,
  new data, Firebase).
- No usability or documentation agent. The session itself looks at the changed screens at 320 px
  (`look.mjs`) and writes the `changelog/` entry; the docs of the lab (its README or its section in
  the game's doc) are updated in the same commit only when what it describes changed.
- Local tests: only the ones for what changed (the page's e2e script and `landing-fold.mjs` if the
  first screen moved, `public/labs/listed.test.mjs` if the `/labs/` card changed). CI runs the rest.
- One push, auto-merge, `wait-pr.mjs`, as always.
Everything else keeps D-304: a PR that takes something out of the lab gets the full usability pass,
and a PR that touches shared code or Firebase rules (even if only for lab key holders) gets both agents.
**Why:** the owner's request. In the lab, few people see the change, the owner checks it right after,
and the agents' short pass found nothing in the last three lab PRs; CI still runs the affected e2e.
**Consequences:** CLAUDE.md's "Before proposing a merge" says it. The full pass is still where the
change reaches everyone (D-304).
