## D-478 · An archived Cup's link shows its podium instead of "not found" (lab)
**Date:** 2026-10-27 · **Status:** current · **Relation:** follows D-476 · **Topics:** cup, rankings
**Context:** the nightly archive (D-476) moves Cups finished more than 733 days ago out of
`torneos/`, so their link said "No encontramos una copa con ese código", as if it had been misspelled.
Their podium stays in `torneoPodios/<code>`, public and read without an account, for the medal table.
**Decision:**
- When a cup code finds nothing (and it was not deleted while open, D-117), La Copa reads
  `torneoPodios/<code>` before the error. If it has a name and a podium, the link shows a memorial:
  🏆 the cup's name, "Terminó el <date with year>", the podium 🥇🥈🥉 in order (ties included), a
  note that it ended a while ago and was archived, **🏆 Crear una copa nueva** (the creator, with
  the same name filled in) and **🥇 Ver el medallero** (`/records/#copas`). No podium, or no network:
  the error of before.
- Only the top three are shown: `torneoPodios` keeps nothing else, and the archived cup is closed
  to clients.
- Behind the lab (D-395, D-409): only with a lab key (`labAccess()`, card `#seccion-copa-archivada`
  in `/labs/`); in the test store, only with `&lab`. Everyone else keeps the error.
- No rule changes. `tools/e2e/cup/archived.mjs` checks it in four languages at 320 px with the test store.
**Why:** a link from two years ago is a memory, not a typo; the podium is already public, so
showing it costs one read and no new data. Offering the same name invites the group to play again.
**Consequences:** going public for everyone is a later decision, once validated in the lab. A
cup opened by its alias (`?pirata`) still says the alias was not found: the archive frees the alias.
