## D-459 · Feedback reports are readable only by the owner; the tools read them with the admin key
**Date:** 2026-10-27 · **Status:** current · **Relation:** amends D-104 (who reads `feedback/`; sending stays without an account) · **Topics:** agents
**Context:** D-104 let anyone read `feedback/` so that `reports.mjs` could fetch the reports
without the owner's account, and said that if that changed, reading would close to the owner's UID.
The reports now carry more than test comments: the name a player typed, the mask of their email,
and the context of where they wrote from. Every tool that reads them already has the owner's admin key
(`feedback.mjs sync` needs it for `feedbackIssues/`), so the open read no longer buys anything.
**Decision:** `feedback/` is read only by the owner's UID (the same condition as the other
owner-only nodes). Writing does not change: anyone still sends a report once, over REST, without an
account. `tools/agents/feedback.mjs sync` and `tools/firebase/reports.mjs` read it with the service
account key (`tools/firebase/firebase-admin.mjs`); the panel already reads it signed in as the owner;
the manual `feedback.yml` fallback passes the `FIREBASE_ADMIN_JSON` secret.
**Why:** data people send is read by the people who answer it, not by anyone with the URL.
**Consequences:** the rules and the tools change in the same PR, because `publish.yml` publishes the
rules on merge. The Mac mini's `feedback-watch` job runs from the main folder, which `jobs.mjs run`
fast-forwards to origin/main before each run, so it picks up the new reader on its next run; if that
folder could not be updated (not clean, not on `main`), the old reader gets HTTP 401 until it is.
