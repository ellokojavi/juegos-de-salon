## D-573 · A red PR its session left is nudged within the hour, and taken over by a cloud task two hours later
**Date:** 2026-11-17 · **Status:** current · **Relation:** extended by D-616 (outside PRs stay unstuck) · **Topics:** agents
**Context:** Sessions stop with their PR red (#1525, #1517 on 2026-11-17 sat for hours), and the only watch was the daily `pending-watch.yml` (D-441), which waits 6 h and only opens an issue. The owner wanted stalls caught fast, cheaply, and with nothing living on the Mac mini.
**Decision:** Each hour, inside the heartbeat (`notifications.yml`, D-569), `node tools/agents/pending.mjs nudge` comments once on each of the owner's open, non-draft PRs whose required check is red with no push for an hour. The comment carries a hidden mark with the head commit, so a push starts over. A cloud session subscribed to its PR (D-522) wakes on it. Two hours after the nudge, still the same commit, the PR is listed by `pending.mjs stalled`, and the cloud scheduled task `stalled-takeover` (prompt `tools/jobs/prompts/stalled-takeover.md`, `where: "cloud"`) fixes it on its branch. Contributor PRs stay with the contributions agent (D-568).
**Why:** Detection costs no model: one script in a workflow that already runs. The model works only when a PR really stalled, and the task ends at once otherwise. Nothing runs on the Mac mini.
**Consequences:** A session on the Mac that stops is covered too: GitHub does not reach it, but the takeover does. If the scheduled task is lost, it is recreated from its prompt file.
