## D-577 · A daily cloud task archives the owner's finished Claude sessions
**Date:** 2026-11-17 · **Status:** current · **Relation:** extends D-252 (sessions and worktrees), D-568 (cloud scheduled tasks); amends D-451 (a Claude round may be a cloud task when it needs no Mac, tools/jobs/README.md says where a job goes) · **Topics:** agents
**Context:** Over 200 Claude Code sessions piled up across every project, most finished days ago, which makes the open ones hard to find. The owner wants the cleanup periodic and living in Claude, not on the Mac mini.
**Decision:** A scheduled task fires daily into a long-lived cloud session, "🧹 Session sweeper" (cheapest model, no repository), because a scheduled task's own session lacks the session tools; it follows `tools/jobs/prompts/session-sweep.md`: it proposes, with a push notification, archiving the sessions of every project that are completed and idle more than 2 days, or review-ready or failed and idle more than 7; it never touches one that is working, blocked or names something the owner must do, and lists those too; it archives only when the owner answers «sí» in the sweeper session, because archiving needs the owner's own confirmation.
**Why:** Archiving can be undone, so a simple rule is safe, and one «sí» a day is the least the confirmation allows; sessions that wait on the owner stay visible. The Mac's worktrees are still cleaned by `clean-worktrees.mjs` (D-252).
**Consequences:** If the task is lost, it is recreated from its prompt file. Its thresholds change only in that file and here.
