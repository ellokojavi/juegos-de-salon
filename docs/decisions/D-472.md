## D-472 · Names in the usage statistics are deleted after 24 months
**Date:** 2026-10-27 · **Status:** current · **Relation:** amends D-463 (the usage statistics now have a deletion date) · **Topics:** agents, home
**Context:** D-463's privacy page had to say the usage statistics had no deletion date, and they hold
the names typed in each game: `stats/<env>/days/<day>/rooms/<code>` (`players`, `end.name`) and
`live/<id>` (`name`). The owner chose 24 months (issue #881).
**Decision:**
- `tools/firebase/stats-retention.mjs` deletes the `rooms/` and `live/` parts of every stats day older
  than `STATS_NAME_MONTHS` (24, counted as 730 days); the day's nameless counts (games, languages,
  hours, pages, countries…) stay. Dry run by default, `--apply` deletes; running it twice deletes nothing new.
- It runs every night as a step of the existing `uad-rebuild` workflow (admin key already there), with
  its `dry_run` input respected. No new scheduler.
- `/privacy/` says 24 months for the names in the statistics in the four languages, and
  `public/privacy/texts.test.mjs` checks the number is `STATS_NAME_MONTHS`.
**Why:** a name typed in a game is personal data; two years is enough to read trends, and the
aggregate counts keep the history without anyone's name.
**Consequences:** a new place in `stats/` that stores a name joins `NAMED` in the tool in the same PR.
The first dry run (2026-10-27) found nothing to delete: the oldest stats are younger than 24 months.
