## D-480 · 🚀 Publicar para todos: the owner sends a lab feature live from its card
**Date:** 2026-10-27 · **Status:** current · **Relation:** extends D-395 and D-409 (everything goes through the lab), D-479 (what launches goes to La Bodega); follows D-365 and D-451 (Mac mini jobs, headless sessions) · **Topics:** structure, agents
**Context:** validating a lab feature ended with the owner asking a session in words to publish it.
The owner asked for a button on the lab's own view, with a confirmation, that a session then takes,
and for the view to say once confirmed that it is not immediate, which PR works on it and where to
watch its status.
**Decision:** each card under 🎲 Juegos en prueba and ✨ Mejoras en prueba gets **🚀 Publicar para
todos**, only for the owner: signed in with the panel's Google account (`🔑 Entrar como dueño` at the
foot of /labs/ when no one is), and only when reading `labsPublish/` works, which the rules allow to
the owner alone. A lab key holder sees nothing new. The button opens a sheet that names the feature,
says what happens and how long it takes (30 to 60 minutes, more for a game; it starts when the Mac
mini is on), and takes an optional note. Confirming writes `labsPublish/<card id>` with
`state: 'requested'`.
The Mac mini's `lab-publish-watch` job (every 5 minutes, `tools/jobs/lab-publish-watch.mjs`) runs a
headless session, through `claude-task.mjs`, only when a request waits. The session follows
`tools/jobs/prompts/lab-publish.md`: it takes the gate off (or the game out of the lab), moves the
card to La Bodega (D-479), runs the review agents and opens the PR from `publish-<card>` with
auto-merge. `tools/agents/lab-publish.mjs` moves the request through
requested → working → pr → merged, or failed with a reason, and the watcher follows the PR on GitHub.
The card shows each state live: while waiting, the delay and a link that finds the PR by its branch;
once open, the PR, its checks (`/pull/<n>/checks`) and its preview (D-429); a failure with why, and
**Volver a pedir**. A request can be cancelled until a session takes it.
**Why:** the owner's request: validating and publishing happen in the same place.
**Consequences:** `firebase/labs-publish.test.mjs` checks the rules (owner only, the shape),
`tools/agents/lab-publish.test.mjs` the states, and `claude-task.test.mjs` the session's tools, which
are the processes round's minus web search. A session that ends without a PR fails its request at
once; one that goes quiet for four hours fails it on the next sync. The job is installed on the Mac
mini with `node tools/jobs/jobs.mjs install` after the merge.
