## D-553 · A lab game's owner merges alone inside their game
**Date:** 2026-11-14 · **Status:** current · **Relation:** amends D-519 (an outside PR is no longer always 🔴) · **Topics:** publishing, agents
**Context:** contributors bring games into the lab; every later PR of theirs was 🔴 and waited for the owner's tick, and the owner's own sessions edited the same games in parallel, so both sides collided on the same features.
**Decision:** `tools/agents/lab-owners.json` maps a lab game to the contributor who brought it in. Their PR from this repo whose every file is inside their games (`public/labs/<game>/**`, `docs/games/<game>.md`, `tools/e2e/<game>/**`, `changelog/*.md`) takes the lane of its files (`outsideReason` in `lanes.mjs`), so it merges on green tests and end-to-end without the owner. Granting ownership is 🔴 (the file is in the red rules): the PR that brings the game in adds the line and the owner's tick approves both. `lanes.mjs check` warns a session that touches an owned game.
**Why:** the owner's approval of the game's entry is the trust decision; repeating it on every tweak only slowed the contributor and invited conflicts.
**Consequences:** seeded with Chanicua's games (flap, memory, sudoku, microgames). Forks stay 🔴. Anything shared (games.js, base.css, another game, Firebase) still needs the owner. Rule in docs/LANES.md.
