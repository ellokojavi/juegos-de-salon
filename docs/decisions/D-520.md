## D-520 · Measurable usability rules are tests; the usability agent judges the rest
**Date:** 2026-11-01 · **Status:** current · **Relation:** narrows D-132 (what the usability agent reviews) · **Topics:** agents
**Context:** the usability agent reviewed every PR by judgment, including rules a program can check
(an emoji mid-sentence, a banned synonym, a button label too long for 320 px, two buttons on top of
each other). A model reviewing a model's output tends to say "looks fine": it cost tokens and still
let measurable slips through (#1086, part 1 of the automation plan).
**Decision:** every measurable U-n is a deterministic check that fails loudly. Texts:
`tools/agents/usability-lint.mjs` over the player's texts in es/en/pt (U-2, U-4, U-5 with
`docs/usability-glossary.json`, U-6, U-17, U-18), run by `tests` through `usability-lint.test.mjs`.
Screens: every e2e screenshot checks U-11 (D-309) and now U-12 (`tools/e2e/spacing-common.mjs`);
U-10 and U-39 stay where they were. Each exception is in `docs/usability-allowlist.json` with its
reason, and an entry that stops hitting fails as stale. `docs/USABILIDAD.md` marks every rule 🤖
(checked), 👁 (judged) or 🤖👁 (both); the agent runs the lint first, never re-reports what it covers
and spends its review on the 👁 part (meaning, tone, U-1, U-7, U-8, U-32…).
**Why:** a check that can fail beats an opinion that says "looks good"; and the agent's time goes
where judgment is needed.
**Consequences:** a new player text that breaks a measurable rule stops the PR in `tests`: fix it in
the three languages or allowlist it with a reason. A newly settled term goes in the glossary. The
budgets were calibrated on main's texts of 2026-10-31 so the first run was green.
