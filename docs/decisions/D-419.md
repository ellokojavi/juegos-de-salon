## D-419 · Auto-merge on every ready PR, unless the owner says not to
**Date:** 2026-10-22 · **Status:** amended by D-519 · **Relation:** amends D-216 (auto-merge by default) · **Topics:** publishing
**Context:** on PR #639 a session opened the PR but did not turn on auto-merge, because its permission check blocked it, and the owner had to ask for it. The owner then set the rule: auto-merge should always happen, "salvo que el dueño indique explícitamente no hacer automerge" (unless the owner explicitly says not to).
**Decision:** owner's rule: every PR that is ready (D-216: the agents are done, their fixes pushed, the `changelog/` entry on the branch) gets auto-merge, with no need to ask. The only exception is the owner saying explicitly, for that PR or that work, not to auto-merge; then the PR stays open without auto-merge, its description says the owner will merge it, and the session reports it that way. A draft or a PR waiting for an owner's decision still is not ready, as before.
**Why:** the owner does not want to be asked for each merge; the checks on `main` are the gate. Leaving the exception only to an explicit word from the owner keeps a session from deciding on its own to hold a PR.
**Consequences:** `CLAUDE.md` (point 4 of "Before proposing a merge") says it, and so do the places that state auto-merge as a rule: C-12 in `docs/CANONES.md` and the agents' guides (`processes.md`, `documentation.md`, `usability.md`, `ideas.md`). If a session's own permission check refuses to turn auto-merge on, that is not the owner saying no: the session tells the owner and asks for the permission, citing this rule.
