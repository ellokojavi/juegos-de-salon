## D-486 · A conflict is a verdict only when it lasts: wait-pr confirms it, and the 🚀 Publicar watcher fixes it
**Date:** 2026-10-28 · **Status:** current · **Relation:** amends D-400 (wait-pr's `conflict`) and D-480 (the watcher follows a publish PR) · **Topics:** agents, publishing
**Context:** two opposite failures with the same root. `wait-pr.mjs` stopped on a single read that
said "conflict", but right after a push GitHub still reports the head before it and recomputes
mergeability lazily: it said `conflict` for #919 and #928, which were mergeable. And the lab's
🚀 Publicar PR #937 was really in conflict with main (three PRs moved cards on `/labs/` that hour):
GitHub ran no checks, auto-merge never fired, and the watcher, which only asked whether the PR had
merged or closed, showed it as under way all night.
**Decision:**
- **`wait-pr.mjs` reports `conflict` only after `CONFLICT_READS` (3) reads in a row** say so, a
  minute apart; a merge, a close or a red required check still stop at once.
- **`lab-publish.mjs sync` reads `mergeable` too.** A conflict is noted (`conflictAt`); one still
  there 15 minutes later (`CONFLICT_MS`) is marked to be fixed (`fixAt`) and the watcher starts, on
  that sync only, one headless session with `tools/jobs/prompts/lab-publish-conflict.md`: it merges
  main into the branch, keeps every lab card once where main has it (this request's own card in
  La Bodega), regenerates the generated files, runs the unit tests and pushes. Anything that needs a
  judgement fails the request with why. A conflict still there an hour after (`FIX_MS`) fails it:
  the card shows ❌ and Volver a pedir. A cleared conflict clears both marks.
- The rules accept the two new numbers, `conflictAt` and `fixAt`, in `labsPublish/<id>`.
**Why:** the owner asked a publish from `/labs/` and nothing happened, with nothing saying why; and a
session's waiter must not send it to fix a conflict that is not there.
**Consequences:** `wait-pr.test.mjs` checks the streak, `lab-publish.test.mjs` the conflict steps
and which sync starts the fix, `claude-task.test.mjs` the new prompt's tool list (no agents: it
only brings the same change up to date). A `conflict` from wait-pr now takes about three minutes.
