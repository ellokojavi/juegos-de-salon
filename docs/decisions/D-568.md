## D-568 · Outside PRs are reviewed by a cloud agent every hour, and the owner is told only when their Yes is the last step
**Date:** 2026-11-17 · **Status:** current · **Relation:** extended by D-616 (outside PRs stay unstuck) · **Topics:** agents
**Context:** Outside contributors open PRs that wait until the owner opens a session to look at them. The owner wanted that work done on its own, and nothing that lives only on the Mac mini: if the machine dies, the know-how must come back by reinstalling from the repository.
**Decision:** The `contributions` agent (`.claude/agents/contributions.md`) runs as a Claude Code cloud scheduled task every hour (prompt in `tools/jobs/prompts/contributions.md`, `where: "cloud"` in `jobs.json`). Its first step, `tools/agents/contributions.mjs check`, lists only the outside PRs (lanes.mjs's rule) with a new commit or comment since its last look, and ends the round when there are none. It comments what is missing, in the contributor's language, and keeps its state in a hidden marker in its own comment, not on any machine. When a PR waits only for the owner's Yes (D-531), `contrib-ready.yml` comments as the workflows bot naming the owner, so GitHub emails them. It never pushes, approves, merges or runs the PR's code.
**Why:** Contributors get an answer within an hour instead of whenever the owner looks; the owner's attention goes only to the final Yes. The cloud task runs on the owner's plan (no variable cost, D-532), Sonnet and the stop-at-nothing first step keep it cheap, and everything but the task itself is in the repository.
**Consequences:** If the scheduled task is lost, it is recreated from its prompt file in one step. The cloud environment needs a `gh` token. A new kind of job, `cloud`, in `jobs.json`.
