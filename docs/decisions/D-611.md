## D-611 · The end-to-end group target is 420 s
**Date:** 2026-11-23 · **Status:** amended by D-624 · **Relation:** amends D-585 (the target, 400 s) · **Topics:** tests
**Context:** Five days after D-585, main sat at the alarm again: ~8,240 s of browser time in the 18 groups, each ~458 s against an alarm at 400 × 1.15 = 460 s, with 1 s of headroom. A lab PR (the quiet cloud, flag `cloud-quiet`) adding one 26 s script turned `groups.test.mjs` red, and so would any new script over ~20 s. The groups are capped at 18 runners, so splitting a script does not help: only the total counts.
**Decision:** `TARGET_S` goes from 400 to 420 s (the owner, 2026-11-23, of the two ways the test offers: raise the target or first cut browser time). The alarm stays at 1.15 × the target, now 483 s.
**Why:** No test is dropped and no screen goes unmeasured (no degradation); each push's end-to-end check takes about 20 s longer, and there is room again for about six minutes of new scripts before the next choice.
**Consequences:** When the headroom the test prints runs low again, the costs round (D-558) cuts browser time first, then proposes the next target.
